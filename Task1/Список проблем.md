**1. Excel-файлы доступны всем сотрудникам без разграничения прав**
- Файл `Patients.xlsx` содержит ФИО, телефоны, адреса, хронические заболевания
- Файлы `Journal-Doctor-FIO.xlsx` содержат записи к врачам с ФИО пациентов
- Любой сотрудник (врач, кассир, бухгалтер) может открыть любой файл
- Может быть массовая утечка персональных данных всех пациентов

**2. Папки пациентов на общем диске доступны для чтения/записи всем**
- Сканы паспортов, медицинских карт, результатов анализов лежат в открытом виде
- Возможность копирования на USB-накопители без контроля
- Может быть утечка данных и медицинской тайны

**3. Полное отсутствие аудита действий с данными**
- Невозможно отследить, кто просматривал медицинские карты пациентов
- Нет журнала изменений в Excel-файлах (кто, когда, что изменил)
- Возможен несанкционированный доступ. Невозможно доказать или предотвратить

**4. Разрозненность систем: 1С не связана с медицинскими данными пациентов**
- В 1С:Бухгалтерия только финансовые операции без привязки к медицинским услугам
- Нет возможности отследить полный цикл: запись → приём → оплата → учёт
- Невозможность аналитики по услугам

**5. Ручная обработка специальных категорий персональных данных (Нарушение 152-ФЗ)**
- Диагнозы, хронические заболевания вводятся вручную в Excel
- Нет шифрования медицинских данных при хранении и передаче

**6. Устаревшие технологии интеграции (OLE)**
- ККМ связаны с 1С через технологию OLE по TCP/IP
- Небезопасный протокол, уязвимый к перехвату данных
- Возможна утечка финансовых данных о платежах пациентов

**7. Отсутствие политик удаления данных (Нарушение 152-ФЗ)**
- Невозможно выполнить требование пациента об удалении его ПДн
- Сканы документов хранятся бессрочно без классификации

**8. Пересылка конфиденциальных данных по внутренней почте**
- Сотрудники могут отправлять сканы документов через Exchange Mail Server
- Нет контроля за вложениями с ПДн
- Может быть утечка через email, попадание данных внешним получателям

**9. Файловый режим работы 1С (файлы .1CD)**
- Данные бухгалтерии и склада в открытых файлах на сервере
- Возможность повреждения или кражи файловой базы
- Может произойти полная потеря финансового и складского учёта

**10. Отсутствие резервного копирования с шифрованием**
- Нет гарантий восстановления данных при сбое
- Резервные копии (если есть) также не защищены
- Может случучиться остановка работы клиники при потере данных
